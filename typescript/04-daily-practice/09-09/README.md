# โจทย์ประจำวัน (09-09-2569): E-Commerce Warehouse Log Auditor
## ระบบตรวจสอบและสรุปบันทึกสินค้าคงคลัง E-Commerce

---

### บริบททางธุรกิจ (Business Scenario)
ระบบคลังสินค้า E-Commerce ขนาดใหญ่ได้รับข้อมูลบันทึกรายการสินค้า (Log) จากระบบจุดขายหน้าร้าน (Legacy POS) ในแต่ละวัน ข้อมูลถูกส่งมาในรูปแบบข้อความดิบคั่นด้วยเครื่องหมายไปป์ `|` ในไฟล์ [rawData.ts](./rawData.ts)

แต่เนื่องจากระบบเก่ามีปัญหาทางเทคนิค ทำให้ข้อมูลที่ส่งมามีความสกปรกและมีข้อผิดพลาดปะปนอยู่ เช่น:
- มีช่องว่างส่วนเกินหัวท้ายและระหว่างฟิลด์
- จำนวนสินค้าเป็นตัวเลขติดลบ หรือเป็นข้อความ (`"three"`) หรือเป็นศูนย์ (`0`)
- ราคาสินค้าเป็นตัวเลขติดลบ
- สถานะคำสั่งซื้อมีหลากหลาย เช่น `PAID`, `PENDING`, `CANCELLED`, `REFUNDED`

ฝ่ายบัญชีและคลังสินค้าต้องการระบบตรวจสอบ (Audit) เพื่อคัดแยกข้อมูลขยะออกไป และคำนวณหายอดขายจริงที่เกิดขึ้น

---

### ข้อกำหนดทางธุรกิจ (Business Acceptance Criteria)

#### 1. การคัดกรองข้อมูลขยะ (Data Cleansing & Validation)
รายการที่ถือว่าเป็น **"ข้อมูลเสียหาย/ขยะ (Corrupted Log)"** และต้องคัดทิ้งทันที ได้แก่:
- จำนวนสินค้า (`quantity`) ไม่ใช่ตัวเลขที่ถูกต้อง (NaN) หรือมีค่าน้อยกว่าหรือเท่ากับ 0 (`<= 0`)
- ราคาต่อหน่วย (`unitPrice`) ไม่ใช่ตัวเลขที่ถูกต้อง (NaN) หรือมีค่าน้อยกว่าหรือเท่ากับ 0 (`<= 0`)

#### 2. การคำนวณและสรุปยอด (Audit & Calculation)
- **ยอดขายสุทธิ (Total Revenue):** คำนวณเฉพาะรายการที่ข้อมูลถูกต้อง และมีสถานะเป็น `"PAID"` (ชำระเงินสำเร็จ) เท่านั้น
  - สูตรยอดเงินของแต่ละรายการ: `quantity * unitPrice`
- **สถิติสถานะ (Status Breakdown):** สำหรับรายการที่ข้อมูลถูกต้อง (Valid) ให้นับจำนวนรายการของแต่ละสถานะแยกไว้ด้วย (มี `PAID` กี่รายการ, `PENDING` กี่รายการ, `CANCELLED` กี่รายการ, `REFUNDED` กี่รายการ)

#### 3. ผลลัพธ์สุดท้ายที่ระบบต้องการ (Audit Report)
ระบบต้องสรุปรายงานออกมาในรูปแบบ Object โดยมีข้อมูลอย่างน้อยดังนี้:
- `totalLogs`: จำนวนบันทึกทั้งหมดที่รับเข้ามา
- `validLogs`: จำนวนบันทึกที่ข้อมูลถูกต้อง
- `corruptedLogs`: จำนวนบันทึกที่เสียหาย/ถูกคัดทิ้ง
- `totalRevenue`: ยอดเงินรวมสุทธิของรายการที่ชำระเงินแล้ว (`PAID`)
- `statusSummary`: ออบเจกต์สรุปจำนวนออเดอร์แยกตามสถานะ
- `paidOrders`: รายการสินค้าที่ชำระเงินสำเร็จพร้อมส่ง

### ระเบียบปฏิบัติ (Rules of Engagement)
1. **ห้ามเริ่มพิมพ์โค้ดทันที:** ต้องเปิดไฟล์ [process.md](./process.md) เพื่อร่าง Input, Processing Pipeline, และ Output Shape ให้เสร็จก่อนเสมอ
2. **ห้ามใช้ Loop แบบเดาสุ่ม:** วางขั้นตอนการแปลงข้อมูลให้ชัดเจน
3. **ตรวจสอบ Edge Cases:** ดักจับ `NaN`, ค่าติดลบ, และช่องว่างให้รัดกุม
