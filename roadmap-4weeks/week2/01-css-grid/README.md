## 1. เครื่องมือหลักของ CSS Grid

- **`display: grid`:** กำหนดให้ Container ทำงานเป็นตาราง 2 มิติ (จัดการทั้งแถวและคอลัมน์พร้อมกัน ต่างจาก Flexbox ที่เน้น 1 มิติ)
- **`grid-template-columns: repeat(3, 1fr)`:** บังคับแบ่งเป็น 3 คอลัมน์เท่ากันเสมอ
  - *ข้อควรระวัง:* ใช้งานได้ดีบนจอคอม แต่จะบีบการ์ดจนพังเมื่อเปิดบนจอมือถือแคบๆ หากไม่ได้คุมด้วย Media Query
- **`repeat(auto-fit, minmax(260px, 1fr))`:** สูตรคำนวณคอลัมน์อัตโนมัติ (Intrinsic Responsive)
  - `minmax(260px, 1fr)`: การ์ดแต่ละใบห้ามแคบกว่า 260px แต่ถ้าเหลือที่ให้ขยายได้เต็มที่ (1fr)
  - `auto-fit`: เบราว์เซอร์คำนวณจำนวนการ์ดต่อแถวตามขนาดหน้าจอจริง โดยไม่ต้องเขียน Media Query ดักจับ

---

## 2. หลักการ Mobile-First & กฎ Cascading

- **Mobile-First Mindset:**
  - เริ่มต้นเขียน CSS สำหรับจอมือถือ (โครงสร้างเรียบง่าย 1 คอลัมน์ ไหลจากบนลงล่าง) เป็นสไตล์ฐาน (Base Styles) เสมอ
  - เมื่อหน้าจอกว้างขึ้น จึงค่อยใช้ `@media (min-width: 768px)` มาขยายร่างหรือเปลี่ยนเลย์เอาต์ (Progressive Enhancement)
  - *เหตุผล:* การต่อเติมความซับซ้อนบนจอใหญ่ ทำได้ง่ายและคลีนกว่าการเขียนจอคอมก่อนแล้วต้องมาตามลบล้างของเดิมบนจอมือถือ (Desktop-First)
- **Cascading Order (ใครอยู่ล่างคนนั้นชนะ):**
  - กฎเหล็กของ CSS: บล็อก `@media` ต้องวางไว้ **ล่างสุดของไฟล์เสมอ**
  - หากวาง `@media` ไว้ด้านบน สไตล์ฐานที่เขียนไว้บรรทัดล่างกว่าจะ Override เขียนทับคุณสมบัติใน Media Query จนไม่แสดงผล

## 3. สถาปัตยกรรม Navbar (Semantic vs Flat)

### การเลือกโครงสร้าง HTML
- **แบบที่ 1: `<nav>` + `<div>` + `<a>` (Flat & Modern)**
  - โครงสร้างกระชับ DOM ไม่ซับซ้อน
  - ไม่มีสไตล์แถมจากเบราว์เซอร์มากวนใจ จัด Layout ด้วย Flexbox ได้ทันที
  - เหมาะสำหรับงานทั่วไปและคอมโพเนนต์ที่ต้องการความคล่องตัว
- **แบบที่ 2: `<nav>` + `<ul>` + `<li>` + `<a>` (Semantic & Accessible)**
  - เป็นมิตรกับ Screen Reader (โปรแกรมอ่านจอจะประกาศจำนวนรายการเมนูล่วงหน้า)
  - ต้องเขียน CSS Reset ลบจุดดำ (`list-style: none`) และระยะขอบ (`margin`, `padding`) ของ `<ul>` ออกก่อนเสมอ
  - เหมาะสำหรับเว็บองค์กรใหญ่ที่ต้องผ่านมาตรฐาน Accessibility ระดับสากล (WCAG)

### การรับมือหน้าจอแคบด้วย Flexbox
- **`flex-wrap: wrap`:**
  - ค่าเริ่มต้นของ Flexbox คือ `nowrap` (พยายามยัดทุกอย่างไว้ในแถวเดียวจนอาจล้นขอบจอ)
  - การใส่ `flex-wrap: wrap` จะสั่งให้เบราว์เซอร์ปัดไอเทมที่เนื้อที่แถวไม่พอลงมาขึ้นบรรทัดใหม่ทันที ป้องกันการเกิดแถบเลื่อนแนวนอน (Zero Horizontal Overflow)

## 4. ตอบข้อสงสัยสำคัญ (Q&A)

### Q1: `auto-fit + minmax()` กับ `Media Query` ในโลกจริงเขานิยมใช้อะไรกัน?
**คำตอบ:** ใช้งานร่วมกันทั้งคู่ โดยแบ่งหน้าที่ตามลักษณะงาน:
1. **ใช้ `auto-fit + minmax()` กับข้อมูลซ้ำๆ (Content-driven Grid):**
   - เหมาะกับแผงสินค้า (Product Cards), แกลเลอรีรูปภาพ, รายการบทความ
   - จำนวนการ์ดไม่แน่นอน และทุกใบหน้าตาเหมือนกัน ปล่อยให้เบราว์เซอร์ตัดแถวเอง
2. **ใช้ `Media Query` (`@media`) กับโครงสร้างหน้าเว็บ (Layout-driven):**
   - เหมาะกับการเปลี่ยนร่างคอมโพเนนต์ เช่น Navbar (แนวตั้งบนมือถือ -> แนวนอนบนคอม)
   - การซ่อน/แสดงแถบ Sidebar เมนูด้านข้าง
   - การปรับขนาดขอบหน้าเว็บ (`padding` ของ `body`) หรือขนาดตัวหนังสือหัวข้อ

### Q2: พอเข้าใจคอนเซ็ปต์ของ Grid แต่ยังนึกภาพการนำไปใช้จริงไม่ออก?
**คำตอบ:** เพราะที่ผ่านมาเราทดสอบกับ "กล่องสีฟ้าเปล่าๆ" ในชีวิตจริง Grid ถูกใช้ 2 งานหลัก:
1. **Component-level Grid (Product Catalog):** ภายในกล่องการ์ดแต่ละใบจะมีภาพสินค้า, ป้ายราคา, รายละเอียด, และปุ่มสั่งซื้อ จัดเรียงเป็นแผงสวยงาม
2. **Page-level Grid (Dashboard Layout):** วางโครงสร้างระดับหน้าเว็บ แบ่งเป็น Header ด้านบน, Sidebar ด้านข้าง, และ Content กลางจอ
