### Semantic HTML
```text

ใช้เพื่อบอกว่า ชิ้นส่วนนี้ทำหน้าที่อะไรในเชิงความหมาย (Meaning) ไม่ใช่หน้าตา (Appearance)
1.<article> : เนื้อหาที่เป็นชิ้นเดี่ยวและสมบูรณ์ในตัวเองเช่น สิ้นค้า 1 ชิ้น, ข่าว 1 ชิ้น เหมาะกับแท็ก <article>
2.<header> : ใช้จักกลุ่มพื้นที่บอกว่านี่คือส่วนหัวนะ ยกตัวอย่างเช่นในการ์ดสินค้าใช้เก็บ รูปกับป้าย
3. <del> : ใช้เพื่อบอกว่าเป็นราคาที่ถูกตัดทิ้ง 
4.type ="button" : ใช้เพื่อระบุว่านี่คือปุ่มจะได้ไม่เกิดปัญหาในอนาคตที่นำไปใช้กับ form
5.aria-label="Decrease quantity" : การบอกว่านี่คือปุ่มอะไรสำหรับคนตาบอด
6. footer : แท็กส่วนท้ายของคอนเท็นนั้นๆ
7.vh ย่อมาจาก viewport : คือหน่วยวัดความสูงของ "หน้าต่างเบราว์เซอร์"
1vh = 1% ของความสูงหน้าจอ
100vh = 100% ของความสูงหน้าจอเต็มๆ (จอคอมสูงเท่าไหร่ หรือจอมือถือสูงเท่าไหร่ ก็จะกินพื้นที่เต็มจอนั้น)
8.box-shadow : 
/* รูปแบบ: [แกน X] [แกน Y] [ความฟุ้ง] [ขนาดการบีบ/ขยาย] [สีและความโปร่งใส] */
box-shadow: 0 10px 25px -5px rgba(0, 0, 0, 0.05);
9.พ่อล้อมรั่ว relative : คือใส่ postion ไม่ให้ตัวลูกหลุดออกไป, ลูกลอยอิสระ absolute : สามารถขยับได้อิสระในกล่องของพ่อที่มี relative แต่ไม่หลุดออกไปโดยใช้ top, bottom, left , right
10. z-index ใช้คู่กับ position เลขเยอะบนสุดเลขน้อยอยู่หลังสุด
```
### DOM & State Machinery
```text
1.document.getElementById('id-name') : ค้นหาจาก ID โดยตรง คืนค่าเป็น HTMLElement | null
2.document.querySelector('.class-name') : ยืดหยุ่นที่สุด ใช้รูปแบบเดียวกับ CSS Selector คืนค่าตัวแรกที่เจอเป็น Element | null
สรุปการใช้ class และ id
ชิ้นไหนที่มี ชิ้นเดียวแน่นอนในทั้งหน้า (เช่น #cart-drawer, #navbar, #login-modal) -> ใช้ ID
ชิ้นไหนที่เป็น ส่วนประกอบที่อาจมีหลายชิ้น หรืออยู่ในการ์ด (เช่น .btn-favorite, .stepper, .price) -> ใช้ Class

element.classList.toggle('class-name');
ถ้ายังไม่มีคลาสนั้นเพิ่ม ถ้ามีแล้วลบ

data-* และ .closest()
data-* Attributes  : การฝากข้อมูลไว้ใน HTML data-ชื่ออะไรก็ได้, ใน TS สามารถอ่านค่านี้ผ่านคำสั่ง element.dataset.action
.closest('button') : ไม่ว่าจะคลิกโดนไอคอนหรือโดนขอบปุ่มให้ปีนขึ้นไปคว้าแท็ก <button> ที่ครอบมันอยู่มาให้ฉันเสมอ

(e: MouseEvent) คืออะไร?
e จะบันทึกข้อมูลทุกอย่างของการคลิก เช่น คลิกตรงพิกัด X/Y ไหน, กดปุ่มซ้ายหรือขวา, และที่สำคัญที่สุดคือ "เมาส์จิ้มลงไปโดนชิ้นส่วนไหน"
ส่วน : MouseEvent เป็นการบอก TypeScript ว่าเหตุการณ์นี้เกิดจากการใช้เมาส์คลิก

 e.target คืออะไร? 
 คือ "วัตถุชิ้นที่โดนปลายเมาส์จิ้มตรงๆ" ถ้าไม่มี .closest() ไม่จับหยิบตัวที่เราคลิกถ้าเป็นไอคอนจับหยิบไอคอนมา
 แต่พอเราใส่ .closest('button') มันจะวิ่งไปจับกล่องแม่ซืึ้งเป็น button
```
### TS
```text
.find()
Syntax: array.find(element => condition)
ex const existingItem = cart.find(item => item.id === 'shoes-01');
: การทำงานของมันคือ:
มันจะหยิบสมาชิกใน cart ออกมาตรวจทีละตัว (แทนด้วยตัวแปร item)
มันถามว่า: "เฮ้ย item ตัวนี้ มี .id === 'shoes-01' ไหม?"
ถ้าเจอตัวแรกที่ตรงเงื่อนไข: มันจะ หยุดเดินทันที แล้วส่ง Object สินค้าตัวนั้นกลับออกมาใส่ตัวแปร existingItem
ถ้าเดินจนหมดแถวแล้วไม่มีตัวไหนตรงเงื่อนไขเลย: มันจะคืนค่าออกมาเป็น undefined
```
### สรุปภาพรวม
```text
1. State-Driven UI (การแยกข้อมูลออกจากการวาดหน้าจอ)
- ตัวแปรใน TS คือ "ความจริง" (State) ส่วนหน้าจอคือ "กระจกสะท้อน"
- เลิกดึงตัวเลขจาก HTML มาบวกลบตรงๆ
- ทุกครั้งที่ State เปลี่ยน ให้เรียกฟังก์ชันกลาง `updateUI()` วาดหน้าจอใหม่เสมอ

2. Event Delegation & Bubbling (การดักจับเหตุการณ์แบบประหยัดแรม)
- ไม่แปะหูฟังแยกทุกปุ่มลูก แต่แปะที่กล่องแม่ (`stepper`) ตัวเดียว
- ใช้ (e.target as HTMLElement).closest('button') ป้องกันปัญหาคลิกโดนไอคอน `<i>` ข้างในปุ่ม
ใช้ `dataset.action` ใน HTML เพื่อแยกแยะว่าผู้ใช้กดปุ่มบวกหรือลบ

3. Immutable State (การจัดการตะกร้าสินค้าโดยไม่แก้ของเดิม)
- ค้นหา: ใช้ `.find()` (คืนค่า Object ตัวที่เจอ หรือ `undefined`)
- เพิ่มของใหม่: ใช้ Spread Operator `[...cart, newItem]`
- อัปเดตของเดิม: ใช้ `.map()` คู่กับ `{ ...item, quantity: ... }` เพื่อสร้าง Object ก้อนใหม่และ Array กล่องใหม่เสมอ ห้ามใช้ `.push()` เด็ดขาด
```

### คำศัพท์
```text
1.State-Driven UI คำแปล: หน้าจอที่ถูกขับเคลื่อนด้วยข้อมูลสถานะ
2.Delegation & Bubbling คำแปล: การผุดขึ้นของเหตุการณ์ (Bubbling) และการมอบหมายให้กล่องแม่เป็นตัวแทน (Delegation)
ความหมาย:
Bubbling: เมื่อคลิกปุ่มลูก เหตุการณ์คลิกจะ "ผุดขึ้น" ไปหากล่องแม่เหมือนฟองอากาศ
Delegation: การใช้ประโยชน์จากการผุด โดยเอาหูฟังไปแปะไว้ที่กล่องแม่ตัวเดียว เพื่อให้ทำหน้าที่เป็นตัวแทนรับฟังคลิกแทนปุ่มลูกทั้งหมด ช่วยประหยัดแรม
3.Immutable State คำแปล: สถานะข้อมูลที่ห้ามแก้ไขของเดิม
ความหมาย: ตัวแปรข้อมูลที่เมื่อสร้างขึ้นมาแล้ว ห้ามไปดัดแปลงไส้ในของเดิมเด็ดขาด (ห้ามใช้ .push() หรือ .splice()) ถ้าต้องการเพิ่มหรือลดข้อมูล ต้องสร้าง Array/Object กล่องใหม่ขึ้นมาแทนที่เสมอ
4.State Machinery คำแปล: กลไกฟันเฟืองควบคุมสถานะ
ความหมาย: ระบบการทำงานหลังบ้านที่เชื่อมต่อกันเหมือนฟันเฟืองนาฬิกา
5.Type Casting  คำแปล: การระบุชนิดข้อมูลอย่างเจาะจง
ความหมาย: การบอก TypeScript ด้วยไวยากรณ์ as หรือ <Type> (เช่น as HTMLButtonElement) เพื่อยืนยันว่า Element ตัวนี้คือแท็กชนิดไหน เพื่อให้ TypeScript ยอมเปิดใช้ฟังก์ชันเฉพาะของแท็กนั้นโดยไม่ฟ้องตัวแดง
6.Immutability คำแปล: ภาวะความคงเดิม (ไม่แปรเปลี่ยน)
ความหมาย: แนวคิดทางวิทยาการคอมพิวเตอร์ที่กำหนดว่า วัตถุที่ถูกสร้างขึ้นในหน่วยความจำจะต้อง ไม่ถูกเปลี่ยนแปลงค่าเดิม เพื่อป้องกันผลข้างเคียง (Side Effects) และบั๊กที่ตามหาต้นตอยากในระบบขนาดใหญ่ (คำตรงข้ามคือ Mutability)
```
